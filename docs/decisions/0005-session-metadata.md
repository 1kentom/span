# 0005: Local session metadata store

Status: proposed. Backend, commands, bindings and client wrappers exist and
are unit tested. No UI calls them yet (see UNVERIFIED).

## Context

The History list should show which agents and models a session used, how
many files changed, a title the user chose, and whether the session is
archived. ACP `session/list` only returns `sessionId`, `cwd`, `title` and
`updatedAt`, so Span has to remember what it observed itself.

Constraints: business logic in `crates/core`, Tauri glue in `apps/desktop`,
IPC types generated by specta, no new dependencies, no data inside the
workspace or `.span`, and no prompt text, file contents or secrets on disk.

## Decisions

### 1. Data model

`span_core::SessionMeta` (TypeScript `SessionMeta_Serialize`), serde
camelCase:

| Field | Meaning |
| --- | --- |
| `agentId` | The UI's agent catalog entry id: ACP registry id for registry agents, preset id for presets, `custom:<executable name>` for a custom command line (the UI assigns those no id, so the caller derives it). |
| `connectionName` | Agent display name when last active. Empty means unknown. |
| `sessionId` | ACP session id. |
| `titleOverride` | User title, trimmed, at most 200 characters. Null means none. |
| `archived` | User flag. |
| `firstSeenMs`, `lastActiveMs` | Unix milliseconds. |
| `models` | `ModelUse { name, effort, usedMs, turns }`, at most 16 (least recently used dropped). |
| `agents` | `AgentUse { agentId, name, role, subagent }`, at most 32. `role` is `delegated` for span-agents children. |
| `filesChanged`, `linesAdded`, `linesRemoved` | Session totals. |
| `stopReasonLast` | Last ACP stop reason. |
| `parent` | `SessionParent { agentId, sessionId }` for a delegated child. |

Zero, empty and null all mean unknown; the UI must not render a field in
that state. Sessions are keyed by `(agentId, sessionId)` because two agents
may reuse an id, so every command takes both.

### 2. Storage

- Location: `<home>/.config/span/session-meta/<hash>.json`, beside the
  existing `session.json` and `recent-projects.json` (the same
  `HOME`/`USERPROFILE` lookup as `SessionStore` and `RecentProjectStore`).
  Never inside the workspace or `.span`.
- File name: `workspace_hash(root)`, 64-bit FNV-1a over `workspace_key(root)`
  as 16 lowercase hex digits. FNV-1a is used because `DefaultHasher` is not
  stable across Rust releases and no hash crate is a dependency. No path text
  appears in file names. A collision between two workspaces would share one
  file; at 64 bits this is accepted.
- `workspace_key` rules (string level, applied to an already canonicalised
  root): a Windows style root (drive letter, `\\server\share`, `\\?\` or
  `\\?\UNC\` prefix) drops the verbatim prefix, uses `/` and is lowercased;
  a unix root keeps case and backslashes; repeated separators collapse; a
  trailing separator is removed except at a filesystem root.
- Layout: compact JSON `{"version":1,"sessions":[...]}`. A higher `version`
  is refused (error, file left untouched) so an older Span never destroys a
  newer one's data.
- Writes: under an exclusive lock file (`<hash>.json.lock`, the same
  `File::lock` pattern as recent projects) the store reads, applies the
  change, evicts, then writes through the shared `atomic_write` (temp file in
  the same directory, fsync, rename). A failed write leaves the old file and
  no temp file.
- Tolerant reads: missing file means empty. Invalid JSON, a wrong shape, a
  missing or zero version, or a file over 2 MiB is renamed to
  `<hash>.json.corrupt` (or `<hash>.json.<n>.corrupt` if that exists, never
  overwriting an earlier copy), a line is printed to stderr with the file
  name only, and the store starts empty. If the rename fails the operation
  returns an error instead of discarding the file.
- Caps: at most 2000 sessions and 512 KiB per written file. Eviction removes
  non-archived sessions first, least recently active first (ties by first
  seen), and only then archived sessions in the same order. Reads accept up
  to 2 MiB so a file from a build with a larger cap is shrunk, not discarded.
- Content: ids, display names, model names, effort labels, stop reasons,
  counters and the user's title. Never prompt text, replies, file contents,
  paths or credentials.

### 3. API (`span_core::SessionMetaStore`)

`list`, `get`, `upsert(SessionMetaPatch)`, `set_title`, `set_archived`,
`delete`, and `prune_missing(agent_id, known)`. Merge semantics of
`SessionMetaPatch`: absent fields keep the stored value; `models` merge by
`name` (turns added, absent turns means 1, zero records a selection without a
turn; `usedMs` set to now; effort replaced when given); `agents` merge by
`agentId`; `filesChanged`, `linesAdded`, `linesRemoved`, `stopReasonLast`
and `parent` are set, not added, so callers send session totals. A patch
creates a missing session and bumps `lastActiveMs`; `set_title` and
`set_archived` create a missing session but do not count as activity.

`prune_missing` is never called automatically: an agent may not list every
session it can still restore, so pruning on a partial list would lose data.

### 4. Commands (apps/desktop/src/session_meta.rs)

| Rust command | TypeScript binding | Client wrapper (`ui/src/lib/client.ts`) |
| --- | --- | --- |
| `session_meta_list()` | `commands.sessionMetaList()` | `sessionMetaList()`, preview returns `[]` |
| `session_meta_update(patch)` | `commands.sessionMetaUpdate(patch)` | `sessionMetaUpdate(patch)` |
| `session_meta_set_title(agent_id, session_id, title)` | `commands.sessionMetaSetTitle(agentId, sessionId, title)` | `sessionMetaSetTitle(...)` |
| `session_meta_set_archived(agent_id, session_id, archived)` | `commands.sessionMetaSetArchived(agentId, sessionId, archived)` | `sessionMetaSetArchived(...)` |
| `session_meta_delete(agent_id, session_id)` | `commands.sessionMetaDelete(agentId, sessionId)` | `sessionMetaDelete(...)`, resolves `true` when removed |
| `session_export_markdown(transcript)` | `commands.sessionExportMarkdown(transcript)` | `sessionExportMarkdown(transcript)` |

All run on a blocking worker. They read the active workspace root, release
the workspace lock, then do file IO, so a slow disk never holds the
workspace. `session_meta_list` returns `[]` when no folder is open; writes
fail with "Open a folder to use session history". In browser preview, writes
and export reject with the usual "requires the span desktop app" message.
Debouncing is the caller's job.

### 5. Where the UI controller should call update

Pure patch builders live in `span_core` (`patch_for_turn_start`,
`patch_for_model_selected`, `patch_for_turn_complete`,
`patch_for_file_stats`, `patches_for_delegation`, `FileChangeStats`) and
`span_desktop_lib::session_meta::patches_from_event` maps an `AgentEvent`
(`config`, `complete`, `delegation.delegated`) to patches for a later
server side caller. Neither `manager.rs` nor `agents.rs` calls them yet.
The UI controller (`agent-controller.ts`) should call `sessionMetaUpdate`:

1. Turn start (after `agentPrompt` is accepted): `{ agentId, sessionId,
   connectionName, models: [{ name: <current model option value>, effort:
   <thought level option value or omitted>, turns: 1 }] }`.
2. Model or effort change (`config` event or `agentSetConfig`): the same
   with `turns: 0`.
3. Turn complete (`complete` event): `{ agentId, sessionId, stopReasonLast:
   event.stopReason }`.
4. Proposal accepted (after `agentReview` or `agentReviewHunks` succeeds):
   the controller keeps per session totals (distinct paths and line counts of
   accepted hunks) and sends `{ filesChanged, linesAdded, linesRemoved }`
   with the new totals.
5. Delegation `delegated` event: lead gets `agents: [{ agentId: agentName,
   name: agentName, role: "delegated", subagent: false }]`; the child gets
   `parent: { agentId, sessionId: lead.sessionId }`. The child's `agentId` is
   the delegated agent name because the event carries no catalog id.
6. History rename, archive and remove call `sessionMetaSetTitle`,
   `sessionMetaSetArchived` and `sessionMetaDelete`; the list merges
   `sessionMetaList()` with `agentListSessions()` by `sessionId` for the
   connected agent.

### 6. Export as Markdown

`span_core::transcript_to_markdown(Transcript, workspace_root, home)` with
`TranscriptItem` tagged by `kind`: `user`, `agent`, `thought`, `tool`
(`title`, `status`), `diff` (`path`, `oldText`, `newText`), `notice`. Each
user item starts `## Turn N`; consecutive tool steps form a bulleted list
under `#### Tool steps`; diffs are unified diffs in a fence longer than any
backtick run inside. The workspace root becomes `.` and then the home
directory `~`, only at path boundaries, in both separator styles for Windows
roots. Raw tool input and output are not part of the record type, so they
cannot be exported.

## Consequences

- History can show agents, models, file counts, titles and archive state
  for sessions Span observed. Sessions created outside Span show only what
  ACP returns.
- Metadata is per machine and per user profile; it is not synced and is
  lost if the profile directory is removed.
- Removing a session from Span's metadata does not delete it from the agent.
- A workspace moved to another path starts with empty history (the key is
  the canonical root).

## UNVERIFIED

- No UI calls these commands yet; the controller wiring in section 5 is a
  plan, not exercised.
- Not run in the native app; only unit tests and the generated bindings.
- Windows: canonicalisation is tested at string level only. Unverified until
  CI: `fs::canonicalize` returning `\\?\` roots that then hash like the
  plain form, `File::lock` on the lock file, `atomic_write` rename over an
  existing file while another handle is open, `USERPROFILE` fallback, and
  the failed write test (it uses unix directory permissions and is
  `cfg(unix)`).
- Concurrency is tested with two threads in one process; two Span processes
  on one workspace rely on the same file lock but were not run.
