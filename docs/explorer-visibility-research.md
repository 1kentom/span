# Explorer visibility and persisted preferences

Checked on 2026-10-29 for [hidden files #69](https://github.com/1kentom/span/issues/69) and the bounded settings part of [Explorer follow-ups #71](https://github.com/1kentom/span/issues/71).

| Primary reference | Observed behavior | Span boundary |
| --- | --- | --- |
| [VS Code Explorer](https://code.visualstudio.com/docs/editing/getting-started/userinterface#_explorer) | `files.exclude` hides entries such as `.git`; `explorer.excludeGitIgnore` separately controls Git-ignore hiding in Explorer. | Make hidden and ignored visibility explicit persisted preferences. Opting in can expose ignored folder rows for lazy, explicit browsing. Version-control metadata stays out of automatic discovery. |
| [VS Code search](https://code.visualstudio.com/docs/editing/codebasics#_advanced-search-options) | Search has separate exclusion settings and an ignore-files toggle. Its performance guidance warns that bypassing ignores can traverse large dependencies and build outputs. | Apply the hidden/ignore choice consistently to ordinary source paths, but keep heavy generated trees out of background indexing/search. State this intentional distinction rather than pretending every Explorer row will be indexed. |
| [Zed settings](https://zed.dev/docs/reference/all-settings#file-scan-exclusions) | Scan exclusions cover the project tree, file finder and search. Inclusions can override Git ignores, but exclusions take precedence. Hidden-file presentation is separate, and `.env*` is a default scan inclusion. | Preserve Span's existing visible dotfile and `.env.example` default. Keep the present ignore default instead of silently widening all environment files. Explicit path access and open-buffer safety are independent of discovery visibility. |
| [Fleet files URL](https://www.jetbrains.com/help/fleet/files-and-folders.html), redirecting to its [retirement announcement](https://blog.jetbrains.com/fleet/2025/12/the-future-of-fleet/) | The former files help redirects; a current hidden/ignored-file contract cannot be verified there. | Do not substitute IntelliJ/Air behavior or claim current Fleet parity. |

The intended settings group is `explorer`: `showHiddenFiles` defaults to true, `showIgnoredFiles` to false, and existing compact-folders/auto-reveal/delete-confirmation preferences retain their true defaults. User and workspace overrides use the existing typed Rust settings, schema and generated IPC. Legacy webview preferences may migrate only when the corresponding typed preference is absent in both scopes.

Ordinary ignored source files can join the tree, file finder and search after explicit opt-in. Explorer directory reads stay lazy and bounded to the requested directory. Background discovery continues to prune dependency trees and recognized ignored build outputs. A directory merely named `build` is not enough to classify it as generated output. Directly opened files still receive normal buffer, save, external-change and workspace-boundary protection even when they are excluded from discovery.

This cut does not claim complete VS Code file nesting, resource decorations or sorting parity. #71 must retain any unimplemented follow-ups. The default remains hidden files visible and ignored files hidden. Protected metadata names are `.git`, `.hg`, `.svn`, `.DS_Store` and `Thumbs.db`. Background scans always exclude directories named `node_modules`. Other recognized outputs are pruned only when ignored: `target` beside a `Cargo.toml`; `dist`, `build`, `.next` and `.nuxt` beside a `package.json`; and `.venv` or `venv` containing `pyvenv.cfg`. Explicitly expanded dependency rows carry an explanation that they are excluded from background discovery. A regular source file named `node_modules` remains eligible.

The existing three native-webview localStorage preferences migrate only when the corresponding leaf is absent in both typed scopes. The migration checks both files first, preserves comments, refuses to write underneath an unsaved settings draft, and clears only backend-confirmed user values. A workspace-only override leaves the legacy global value available for a different workspace. Browser preview settings remain an in-memory fixture and do not migrate native preferences or promise disk persistence.
