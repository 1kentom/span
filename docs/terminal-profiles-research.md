# Installed terminal profiles

Checked on 2026-10-29. This cut makes the installed shell visible and lets the user start another installed shell from the terminal toolbar. The existing new-terminal action retains the default shell.

Profile discovery examines absolute shell paths only, checks that each candidate is an executable file, and collapses aliases of the same named executable. Unix discovery includes the configured shell, common shell locations, absolute PATH directories, and `/etc/shells`. Windows discovery includes the configured command processor, standard cmd/PowerShell locations, and known executable names in absolute PATH directories. Discovery never executes a shell. The backend resolves every supplied profile identifier against a fresh inventory, so the UI cannot provide an arbitrary executable or command line as a profile.

The generated Rust-to-TypeScript IPC contract supplies the profile inventory and creation argument. `TerminalInfo.shell` reports the actual launched path. Command PTYs for explicitly requested Markdown Run are separate from interactive new-shell profile selection, and retain their own explicit language and stale-workspace checks.

Backend verification: 14 terminal-crate tests pass in the release profile, including executable discovery, invalid profile rejection, selected-shell identity, atomic multiline Bash execution, Unicode, workspace validation, output before exit, interrupt, backpressure, and owned-child cleanup.
