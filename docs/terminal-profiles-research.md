This cut makes the installed shell visible and lets the user start another installed shell from the terminal toolbar. The existing new-terminal action retains the default shell.

Profile discovery examines absolute shell paths only, checks that each candidate is an executable file, and collapses aliases of the same named executable. Unix discovery includes the configured shell, common shell locations, absolute PATH directories, and `/etc/shells`. Windows discovery includes the configured command processor, standard cmd/PowerShell locations, and known executable names in absolute PATH directories. Node REPL and Python REPL entries are added only when a known executable is found, with fixed interactive arguments. No debug terminal is advertised. Discovery never executes a shell. The backend resolves every supplied profile identifier against a fresh inventory, so the UI cannot provide an arbitrary executable or command line as a profile.

The generated Rust-to-TypeScript IPC contract supplies the profile inventory and creation argument. `TerminalInfo.shell` reports the actual launched path. Command PTYs for explicitly requested Markdown Run are separate from interactive new-shell profile selection, and retain their own explicit language and stale-workspace checks.

## Compact interactive prompts

[VS Code shell integration](https://code.visualstudio.com/docs/terminal/shell-integration#automatic-script-injection) documents startup injection through arguments and environment variables. Its official [zsh environment wrapper](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-env.zsh) and [rc wrapper](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-rc.zsh) forward user startup files and restore their ZDOTDIR context. Span uses its own small per-session wrappers following that startup-forwarding approach, with owner-only temporary directories retained until the terminal closes. It does not edit dotfiles.

The zsh wrapper loads the user's original startup files in zsh's normal interactive order, respects ZDOTDIR changes and export state, repairs the macOS default history path after the global rc file, and preserves user aliases, functions, completion definitions, options, and existing prompt hooks. Bash forwards the existing `.bashrc` and chains scalar or array prompt commands using the version's existing array semantics. The deliberate customization is the prompt display: current folder basename and optional Git branch, with no right-side clock or full-path prompt. Other shells retain their own prompt behavior.

Powerlevel10k reorders its own prompt hooks and can refresh prompts asynchronously. Span therefore keeps its own precmd hook after existing hooks and adds a standard `add-zle-hook-widget` line-pre-redraw callback. It restores a cached prompt only when the theme changed the prompt strings. It does not replace existing widgets, run Git per keystroke, or use a startup sleep. Prompt values are escaped according to the user's existing zsh prompt options; Bash supports `promptvars` both enabled and disabled. Filenames and branch names containing dollar substitution, backticks, percent directives, or control characters cannot become command source or terminal control sequences.

Limits: the verified integration covers ordinary interactive zsh and Bash startup plus explicit fixtures, including the developer's installed Powerlevel10k setup. Unusual configurations that replace the shell, replace hook arrays later, disable rc processing, or depend on the temporary ZDOTDIR value observed by global system startup files require their own native checks. This is not a claim that every third-party prompt/plugin configuration has been tested.
