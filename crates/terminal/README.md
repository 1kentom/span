# Interactive terminal

`span-terminal` owns user-started PTYs through portable-pty 0.9.0. Unix uses native PTYs, and Windows uses ConPTY. The shell starts directly with an explicit canonical directory inside the open workspace. No command string is built from a path. Finder launch environments receive an augmented child-only PATH.

`TerminalManager::create` returns `TerminalInfo` and a bounded Tokio event receiver. The desktop bridge drains that receiver into the Tauri channel supplied on create. The listener exists before shell output can be forwarded. It forwards one output chunk at a time and waits for the acknowledgement sent after xterm's write callback. This bounds transport messages when rendering is slow. A failed channel closes its session. Hiding the dock preserves the session.

Rust DTOs derive `specta::Type`. Export them through the existing generated IPC contracts. The panel's `TerminalTransport` is a local UI adapter contract, rather than an independently declared serialized IPC model.

PTY reads use dedicated threads. Spawn, writes, resizing and termination use Tokio's blocking pool. Output chunks are at most 8 KiB, the receiver holds at most 64 events, and backend scrollback holds at most 256 KiB. Input is limited to one MiB per call, dimensions to 2 through 1000, and a workspace to 12 sessions. The frontend xterm display retains 5000 lines.

Explicit close stops the foreground process group and shell. On Linux and macOS, it also scans for processes in the PTY's private session and signals those members before releasing PTY handles and reaping the child. Other Unix targets retain foreground and shell cleanup. Windows sessions use a Job Object that terminates assigned descendants on close. Manager drop also cleans up owned sessions. This does not guarantee cleanup of processes that deliberately detach into another session. The desktop closes all sessions before replacing a workspace and waits for cleanup at final application exit, after the frontend's unsaved-buffer review. Terminal IDs include the workspace epoch, so old writes and acknowledgements cannot target a new workspace's shell. Commands may have side effects before termination.

Markdown Run is an explicit user action. Send stages exact text in a reviewable draft with a separate Run draft button. It does not write multiline text to a shell, because intermediate newlines could execute commands. Nothing executes during Markdown rendering. This terminal does not advertise ACP terminal tools or grant an agent execution permission.

Nine real PTY tests on macOS cover UTF-8 I/O, native resize, cwd and symlink rejection, spawn failure, ordered final output and exit status, Ctrl-C, foreground and background job cleanup on close and drop, bounded scrollback, writer destruction with a full native output buffer, and close during output backpressure. Four desktop bridge fixtures use real PTYs to check acknowledgement flow control, disconnected consumers, workspace replacement and stale IDs, rooted directories and the write/resize/interrupt/scrollback commands. Cross-platform fixtures include Windows command variants. The crate passes a Windows GNU all-target compile check; Windows and Linux runtime behavior still require native validation on those operating systems. The browser preview cannot execute native PTY processes.
